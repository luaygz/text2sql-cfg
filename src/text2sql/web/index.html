Grammar-constrained text-to-SQL

Each candidate query below was decoded under a context-free grammar built from the database schema, so the model can only write a read-only SELECT over tables and columns it is allowed to see. The trace shows every stage live: the grammars, the candidates, how their results cluster and vote, the selected SQL and its result. Every run calls the OpenAI API and counts against this server's spend cap.

Ask a question

Simulated login

This is a multi-tenant database. Whose rows a query can read is decided by the identity you sign in with here, which the server keeps in its own session and sends to the browser only as an opaque HttpOnly cookie. Nothing you type in the question, and no tenant id in the request body, can change it: the scoping layer adds the session's tenant (and user) filter to every table the query touches.
